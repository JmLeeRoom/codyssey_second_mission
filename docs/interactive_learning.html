    📚 자료구조 학습 랩 & 셀프 퀴즈

    게임 기본 퀴즈의 5주제(스택 · 큐 · 해시 테이블 · BST · 이진 탐색)를 직접 조작하며 이해하고, 게임과 같은 채점 방식의 10문항 셀프 퀴즈로 확인합니다.

    구성 A — 주제 탐험

    Push / Pop을 눌러 보세요 — 값은 자동으로 생성됩니다. (최대 7개)

    LIFO — Last In, First Out (후입선출)

    나중에 push한 데이터가 가장 먼저 pop됩니다. 추가와 제거가 모두 맨 위(top)에서만 일어나기 때문에 push · pop 둘 다 O(1)입니다.

    대표적인 예가 함수 호출 스택입니다. 이 프로젝트에서도 main() → QuizGame.run() → play_quiz() → ask_int() 순서로 호출이 쌓였다가, 반환은 정확히 역순으로 일어납니다.

    그 밖의 활용: 실행 취소(Undo), 괄호 짝 검사, 깊이 우선 탐색(DFS).

    Enqueue는 뒤(rear)에 넣고, Dequeue는 앞(front)에서 꺼냅니다. (최대 7개)

    FIFO — First In, First Out (선입선출)

    먼저 들어간 데이터가 먼저 나옵니다. 뒤(rear)로만 넣고 앞(front)에서만 꺼내므로, 양 끝 연산 기준으로 enqueue · dequeue 모두 O(1)입니다. (파이썬에서는 collections.deque가 이 조건을 만족합니다.)

    활용: 프린터 대기열, 작업 큐, 그리고 그래프의 너비 우선 탐색(BFS) — 먼저 발견한 정점을 먼저 방문해야 하므로 큐가 필수입니다.

    예시 키:
    키를 입력하면 문자코드 합 → % 7 → 인덱스 계산 과정이 여기에 표시됩니다.

    해시 함수 — 키를 인덱스로

    해시 함수는 키(Key)를 계산해 저장 위치(인덱스)로 바꿔 줍니다. 이 랩의 해시 함수는 sum(문자코드) % 7 — 어떤 키든 0~6 사이의 버킷 번호가 나옵니다. 위치를 계산으로 바로 찾기 때문에 저장·조회가 평균 O(1)입니다.

    충돌(Collision): 서로 다른 키가 같은 인덱스로 계산되는 현상입니다. 이 랩은 같은 버킷 안에 이어 붙이는 체이닝으로 처리합니다. melon과 lemon은 같은 문자들의 순서만 다르므로 문자코드 합이 539로 같습니다 — 저장해 보면 버킷 0에서 충돌합니다.

    파이썬의 dict도 내부적으로 해시 테이블입니다. 충돌이 몰리면 한 버킷의 체인이 길어져 최악의 경우 O(n)까지 느려집니다.

    왼쪽 < 부모 < 오른쪽 · 중복 값은 무시됩니다 · 시각화 깊이는 4단계까지

    값을 삽입하면 루트부터 비교해 내려가는 경로가 표시됩니다.

    이진 탐색 트리 — 왼쪽 < 부모 < 오른쪽

    모든 노드에서 왼쪽 자식 < 부모 < 오른쪽 자식 규칙이 유지됩니다. 새 값은 루트부터 비교하며 내려가 빈자리에 붙습니다 — 비교할 때마다 반대쪽 서브트리를 통째로 건너뛰므로 탐색·삽입이 평균 O(log n)입니다.

    단, 10, 20, 30, 40처럼 정렬된 순서로 넣으면 오른쪽으로만 자라는 편향 트리가 되어 최악 O(n)이 됩니다. 직접 넣어서 확인해 보세요.

    이 랩의 BST는 이미 있는 값(중복)을 만나면 삽입하지 않고 무시합니다.

    비교 0회

    L = low · M = mid · H = high · 🎯 = 발견 위치

    범위를 절반씩 버리는 O(log n)

    정렬된 배열에서 가운데(mid)와 목표값을 비교해, 목표가 작으면 오른쪽 절반을, 크면 왼쪽 절반을 통째로 버립니다. 남는 범위는 low ~ high로 관리합니다.

    이 15칸 배열을 앞에서부터 훑는 선형 탐색이면 최대 15회 비교해야 하지만, 이진 탐색은 최대 4회(⌈log₂16⌉)면 끝납니다. 데이터가 100만 개여도 약 20회 — 이것이 O(log n)의 힘입니다.

    전제 조건: 배열이 정렬되어 있어야 합니다. 정렬이 안 되어 있으면 절반을 버리는 판단 자체가 성립하지 않습니다.

    구성 B — 셀프 퀴즈 (10문항)

    게임 기본 퀴즈 5문항 + 같은 주제의 보강 문항 5문항. 게임과 동일하게 힌트를 쓴 문제는 맞혀도 0.5점만 인정되고, 최종 점수는 round(획득 점수 ÷ 10 × 100)입니다.

    주제 1 / 10

    ⚠️ 힌트 사용으로 이 문제는 맞혀도 0.5점만 인정됩니다.

    CLI 회차는 실제 state.json의 게임 기록, Lab 회차는 이 페이지의 셀프 퀴즈 기록입니다. 막대에 마우스를 올리면 상세가 보입니다. (y축 0~100점 고정)

    🎉 흐름 완료 — clone과 pull은 언제 어느 쪽을 쓰는가

    clone = 새 복제본 생성
    • 로컬에 아무것도 없을 때, 처음 한 번 실행
    • 원격 저장소 전체(커밋 이력·브랜치 레퍼런스·현재 파일)를 통째로 내려받아 새 디렉터리를 만듦
    • origin이 자동 등록되고 main의 upstream까지 설정됨 — 이후 -u 없이 push 가능
    • .gitignore에 걸린 state.json은 이력에 없어 복제되지 않음
    pull = 기존 저장소 동기화
    • 이미 저장소가 있고 일부만 뒤처져 있을 때 실행
    • 원격의 새 커밋만 가져와 현재 로컬 브랜치에 반영함
    • 이번 실습에선 원본에 새 커밋이 없어 Fast-forward로 포인터만 전진
    • 이미 등록된 원격(origin)을 그대로 사용
